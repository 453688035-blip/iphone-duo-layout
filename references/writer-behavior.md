# AdaptFlow writer behavior

## Generate with AdaptFlow or a Figma writer

1. In Figma Desktop, select one or more visible original frames on the current page and run AdaptFlow. Frames directly inside a section count as sources; generated `[AdaptFlow]` frames do not. Frames need to be unrotated, with unlocked aspect ratios and without width or height variable bindings. Each selected source uses the same targets and gets its own row. When a chat result is missed, select that source alone and choose a movable result in **Specify chat result** (panel label `指定对话结果卡`). Preserve the surrounding heading and follow-up actions.
2. With a Figma writer, clone each source independently for every target, record the source-to-target node mapping, and apply the plan to editable layers. Preserve existing output unless replacement is requested. If a write fails partway, clean up the incomplete frames from that run. Use separate frames for compact list/detail states, separate split windows, or presentation states when they need distinct interactions.
3. Keep root fills and source layer order. Expand full-bleed backgrounds separately from scrollable foreground. Check nested and locked backgrounds, gradient/image fills, and image cropping. When the preview already has an authored top bar, check for double reservation. Use measured reservations for device delivery.
4. The plugin directly reflows supported list/detail pairs, forms, recognized chat, report, and empty-state layouts, and absolute-layout pages that do not use Auto Layout. For those pages it widens full-width rows to the usable content area, keeps fixed layers at their size, moves them with their Figma constraints, and gives content taller than the window a vertical scroll instead of clipping it. Instances, text, and icons are never stretched. An authored top bar is detected and reused, so the target does not reserve the 84 pt toolbar a second time; the report notes this as `existing-top-bar-used`. Use the navigation and modal rules to review or edit component variants, sheets, and complex media layouts. Read back actual frame geometry before reporting that a layout was generated.

5. Empty bands in a generated frame come from three causes, and the plugin now handles each one. A **wide window** fills the usable area by default (panel option **Wide-window content**, `撑满可用区` / `阅读宽度居中`): full-width rows, the composer, and app bars follow the window, and equal-width siblings such as checkbox columns or card grids share the extra width instead of hugging one side. The centred alternative keeps a 580 pt reading measure and reports `reading-width-gutter` with the exact gutter width, so an intentional margin is never silent. A **narrow window** stacks those equal-width siblings into one column (`stacked-single-column`) and lets fixed-width text re-wrap, instead of clipping the right column. An **outer navigation strip** is reserved when the source carries a bottom bar or side rail. Without it, the report adds `navigation-area-unreserved`. For the inner portrait and tabletop presets, the writer uses 24 pt of Home clearance when the source has no bottom navigation and reports `bottom-navigation-area-compacted`. An authored bottom bar keeps the 95 pt template reservation. Custom targets retain their supplied insets.

6. The generated frame is the window, so the writer re-rounds its outer silhouette for the target. It takes the largest authored corner radius from the source frame and its full-bleed surface layers (including a `[af:background]`), applies it to every device corner, and keeps the hinge edge at 0 for `duo-split-left` / `duo-split-right`; book and tabletop stay fully rounded. The frame is then clipped, so a square-cornered background cannot repaint over the rounded corners. A square source is left square — the writer never invents a radius — and a corner bound to a variable is reported as `corner-radius-bound` (R029 / R079) instead of being overwritten. When the source was prepared from a device render — a body or backdrop with the app inside a screen layer — the window takes the **screen** layer's paint and radius instead of the body's: the frame and the full-bleed body layers are repainted with the screen colour, so the reserved status and navigation strips read as app background rather than as a grey shell, and the corners are the screen's. A square screen falls back to the body radius. Sources that are already the screen keep their own paint; the adopted layer is reported as `surface: { name, radius }`.

7. Reserved system strips can be filled with Apple's official components instead of staying blank. With the panel option **填充官方系统组件** on (the default), the plugin looks for Apple's [iOS and iPadOS 27 kit](https://www.figma.com/community/file/1651309003795292092/ios-and-ipados-27) among the libraries enabled in the file and imports its Status Bar / Home Indicator by component key into the reserved top and bottom strips, stretching them to the window width. Enable the kit as a published library first: open it from Community, move the copy into a team project, publish it, then enable it under **Assets → Libraries** in the design file. Navigation and tab bars are app content, so the writer never fabricates them and keeps reusing the authored layer. When the kit is not enabled the writer keeps the strip blank or draws a placeholder Home indicator bar and reports `native-chrome-fallback` (R032 / T032). When the kit is enabled but the component set itself carries authoring errors, Figma refuses to instantiate it; the writer keeps the strip and reports the same code with an "instancing failed" detail instead of pretending the library is missing. Instances in the source that come from such a broken set are read as unknown during the audit rather than aborting the batch. For side-rail Duo targets, the writer inserts a matching inner/outer vertical variant when a right strip is reserved. The outer landscape preset skips automatic status insertion, matching its Layout Guide. It skips insertion when the visible source already has an authored status module. A reused authored top bar leaves no top strip for a horizontal status bar; split windows reserve neither system strip. Inserted chrome is named `[af:chrome] …` and is excluded from geometry validation.

The pose cards are drawn at each preset's own ratio (outer 466 × 678, inner 951 × 669, split pane 466 × 669) and follow Apple's HIG pose set, so a thumbnail never promises a silhouette the generated frame will not have; all eight poses start selected and the last used combination is remembered in `figma.clientStorage`. The panel always generates from the live canvas selection: switching artboards and pressing generate uses the newly selected frame, and the panel re-reads the selection when it regains focus. Generation reports determinate progress with a percentage and the target being processed. If the source changes while a run is in progress — including Figma resolving instance content after a zoom — the run keeps the frames it already made and reports `source-changed` or `source-layers-added` as review items instead of cancelling the batch. The built-in sample frames (列表与详情 / 组件表单 / 对话与结果) use Chinese copy and the first available system CJK font (PingFang → Noto Sans SC → Microsoft YaHei → Hiragino Sans GB → Inter), so the demo reads like the panel rather than like filler text.

Use these optional layer-name prefixes with a following space and the original layer name.

| Prefix | Use |
| --- | --- |
| `[af:list]` or `[af:sidebar]`, with `[af:detail]` | Two independent direct child frames, excluding a recognized full-bleed background. Expanded targets put them side by side where they fit. Compact targets show separate list and detail states. |
| `[af:open-detail]` and `[af:back]` | One corresponding control per pane. If both can accept prototype links and have no existing interactions, the plugin can connect the compact states. Review existing links. |
| `[af:fields]` | Direct Auto Layout field group in a vertical Auto Layout source. |
| `[af:chat]`, `[af:composer]`, `[af:result]` | Chat source, independent bottom composer, and movable result. |
| `[af:continuous]` | Continuous reading root or container that can span a soft division. Check its interactive children individually. |
| `[af:status]` | Authored status component (including its camera when applicable); prevents the plugin from inserting a second status module. |
| `[af:nav]` | Bottom bar or side rail. It preserves the preset navigation reservation. A layer named explicitly as a side rail does not trigger the 95 pt bottom reservation. |
| `[af:control]`, `[af:navigation-control]`, `[af:critical]` | Complete touch target, navigation target, and essential foreground. |
| `[af:content]`, `[af:decoration]`, `[af:background]` | Foreground, decorative branch, and bottommost full-bleed background. |

## Review and hand off

In the plugin report, use **Locate frame**, **Locate region**, and **Locate layer** (panel labels `定位画板`, `定位区域`, and `定位图层`). `contentArea` and `reservedRegions` describe the plan. When available, `layoutRegions` gives the generated viewport's position, size, and fixed or scrolling behavior.

- **One side is blank.** Determine whether there is an independent result, detail, or report module. Mark the real region if it was missed. Confirm each pane has a purpose, or center a readable single-column layout in its chosen region.
- **One side has square corners.** Compare the target window with its geometry: only a split window keeps a flat hinge edge. In 内屏横向 / 内屏竖向 / 书本 / 桌面 every corner is a device corner. If the generated frame still shows the source's split-pane silhouette, the source radius lives in a layer the writer does not treat as a surface — put the radius on the root frame or a `[af:background]` layer.
- **A grey band sits beside the content.** The source is a device render whose app screen is inset inside the body (a bezel, a status strip, or a hinge edge). Only the body was resized, so the uncovered body stayed an empty plate. The writer recognises the shell, stretches the screen over the usable area, repaints the body with the screen paint and corners, and hides bezel decorations (`device-bezel-hidden`). If a band still stays grey, the screen is not a direct child or the body has no opaque fill and rounded corners — put the app inside one rounded frame layer on the body and regenerate.
- **The background stops at the old phone width.** Compare the source fill and nested background layers. Check all four edges, stacking order, and image cropping on the target. A layer that still only reaches the source width inside an absolute-layout page is reported as `content-wider-than-area`; the usual causes are a fixed width, a mask, or a locked layer the writer intentionally left alone.
- **The panel looks older than the build.** Compare the version badge in the panel header (`v0.5.2`) with `PLUGIN_VERSION` in `main.mjs`. A mismatch, or a missing badge because the panel still renders an older layout, means Figma kept the previous `ui.html` in memory: close the panel, quit Figma, then import `../figma-plugin/manifest.json` again. The panel also warns on its own when `init.version` differs from `UI_VERSION`. The dark `</>` square in the Figma window title bar is Figma's placeholder icon for development plugins and is not part of the panel — it is only replaced by the icon uploaded when publishing (see `../figma-plugin/assets/icon-512.png`).
- **Text sits in a bar area.** Content that only spills into a reserved toolbar, rail, or safe-area band is reported as a warning, because reading layout often runs under an overlay. Controls and foreground that leave the window stay blocking.
- **A control is clipped or outside the usable area.** Inspect the actual target-local hit area and the active camera, fold, or toolbar bounds. A scrolling viewport may intentionally hide items below its first screen. Verify the last item scrolls clear of the bars and can be activated. For chat, measure the thread bottom, composer top, and usable bottom.
- **A role or interaction was missed.** Locate the relevant source layer, correct its role or choose an existing component variant, and retry the affected target. Keep structural warnings open when the evidence is insufficient.

Check the exact frame geometry, fills, readable margins, complete hit areas, overlap and clipping, scroll end, font and text styles, instances, variables, and prototype links against the source. Test outer portrait and short landscape, flat inner display, book and tabletop, and both split windows. Review larger text, long labels, RTL, light and dark appearance, keyboard, modal dismissal, focus, and reading order. In the prototype or app, check that moving between windows or postures preserves route, destination, selected item, draft, validation, scroll anchor, focus, and playback. Use motion that keeps controls recognizable and respects Reduce Motion.

For a quick Figma pass, generate the same chat on a book preset and a narrow split preset. Check that the result occupies a separate usable region in book and stays with the messages in the narrow window. Use a list and detail source to verify compact navigation in Present mode, and a bound form to confirm its field instances and variable bindings after stacking.

For every output, include source and target IDs, window size and provenance, applied layout and navigation, deviations from the template, and the affected layer IDs for blockers. Give actual Figma readback for editable output. Report automated geometry checks, Figma visual review, and runtime or device verification separately. Mark unresolved structure or missing verification where it affects delivery.
