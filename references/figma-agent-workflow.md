# Figma Agent 折叠屏适配流程

此流程适用于从现有 Figma Frame 生成或审查可编辑的折叠屏设计。窗口尺寸、姿态和设备预设见 [AdaptFlow 规则](adaptflow-rules.md)。

## 使用本地 Writer

按 [插件维护说明](../../figma-plugin/SKILL.md) 导入开发插件。插件接收当前页上的一个或多个原稿 Frame。框架本身需可见、无旋转、未锁定比例，宽高无变量绑定。Frame 可以直接挂在画布上，也可以放在 Section 内；已生成的 `[AdaptFlow]` 稿不会被当作原稿。多选时按原稿分行生成。指定对话结果卡时单独选中该原稿。

面板始终以画布当前选择为准：切换到另一张画板后直接生成，用的就是新画板，面板重新获得焦点时也会同步一次选择。生成过程中显示百分比进度和当前目标，缩放画布或查看其他画板不会中断；若原稿在生成期间确实发生变化，本次结果按开始时的版本产出，并在报告中给出 `source-changed` 或 `source-layers-added` 供复核，而不是丢弃整批结果。

先用自动识别生成。对话结果未命中或命中错误时，在面板展开「指定对话结果卡」，按图层路径选择原稿中的独立卡片。结果卡可嵌在普通 Frame 内。涉及蒙版、与相邻图层重叠或位于实例内部的卡片，需要先确认其可移动边界。其他语义可使用下表标记，标记后加空格并保留原名称。插件在生成时只写入克隆稿。

| 标记 | 应用位置和行为 |
| --- | --- |
| `[af:list]` 或 `[af:sidebar]` 与 `[af:detail]` | 两个独立、无旋转的普通 Frame，是原稿仅有的两个可见直接子层。宽区保留双栏。窄区生成分别显示列表与详情的两个 Frame。 |
| `[af:open-detail]` 与 `[af:back]` | 各放一个在对应内容区中，使用可设置原型交互的热区。两者均无已有交互时，自动添加紧凑列表到详情及返回连线。已有连线保留并提示复核。 |
| `[af:fields]` | 垂直 Auto Layout 原稿中的直接字段组，字段组本身使用水平或垂直 Auto Layout。宽度不足时把横排转为纵排。优先用可伸缩的实例与容器，保留每个实例的属性和变量。 |
| `[af:continuous]` | 放在连续阅读页根 Frame 的名称开头，允许页面在软折叠区保持连续。也可标记具体可连续滚动的容器。 |
| `[af:chat]`、`[af:composer]`、`[af:result]` | 可分别标记对话原稿、底部独立输入栏和独立结果卡。自动识别也可读取常见的输入提示和结果标题。 |
| `[af:control]`、`[af:navigation-control]`、`[af:critical]` | 用于标记完整热区、自定义导航热区和关键前景元素。 |
| `[af:content]`、`[af:decoration]` | 用于标记普通前景或纯装饰分支，辅助几何校验。 |
| `[af:background]` | 用于标记原稿底层、接近铺满画板的纯背景。可保留原有渐变或图片填充，随目标画板尺寸铺满。 |

插件包含 8 种预设和一个自定义窗口入口。窗口 JSON 结构见 [CLI 和规则接口](adaptflow-rules.md#cli-和规则接口)，面板只需粘贴示例中的 `target` 对象。生成稿放在当前画布已有图层的右侧，重复生成会保留此前版本。JSON 报告包含源到目标的节点映射、窗口来源、导航建议、阻断问题和人工复核项。

报告与团队验收矩阵（`iPhone_Duo_全状态适配规则_设计开发验收矩阵.xlsx`，83 条规则 R001–R083、83 项测试 T001–T083）联动：已知 issue code 在 `scripts/rule-map.mjs` 中映射到规则 ID、对应测试 ID 和优先级（P0/P1/P2），报告每条 issue 带 `rules` 字段，面板在问题右侧显示 `R0xx · P0` 徽标。填写测试验收表时，把 `rules.tests`（如 T025）和受影响画板名抄入对应行的「问题编号 / 备注」。8 个预设覆盖矩阵 12 种状态中的 S01–S06、S08；帐篷式（S07）、画中画/键盘（S09）、双 Scene（S10）、折叠过程（S11）与旧 SDK 兼容（S12）需要人工处理，详见 SKILL.md 的覆盖表。页面类型上，插件自动识别的列表详情 / 表单 / 对话 / 仪表盘分别对应矩阵模板 P02 / P04 / P05 / P01；其余 8 类页面（搜索、图库、视频、地图、编辑器、相机、商品、游戏）按人工规则处理。

插件当前会直接调整已标记的列表详情、字段组、可识别的容器，以及没有使用 Auto Layout 的通栏页面：整宽的行跟随可用内容区变宽，固定尺寸的图层只按约束移动、不拉伸实例与文字，高于窗口的内容改为纵向滚动。原稿自带顶部栏时，目标稿复用该顶部栏而不再重复预留 84 pt，报告记为 `existing-top-bar-used`。已有导航组件变体切换、复杂媒体与网格结构重排需按规则人工应用。遮挡校验使用已经提供的区域和已识别的前景边界，交付时仍需结合截图、原型和设备测试。仍停在原稿宽度的图层记为 `content-wider-than-area`，通常来自固定宽度、蒙版或锁定图层。

两侧空白按窗口与原稿的宽度关系处理。宽窗默认为撑满：顶栏、输入栏、整宽行跟随可用区，等宽同级图层（勾选列、卡片网格）平分多余宽度；面板「宽窗内容」可切到阅读宽度，按 580 pt 居中并在报告里给出每侧留白（`reading-width-gutter`）。窄窗把等宽同级图层改为单列堆叠（`stacked-single-column`），固定宽度文字改为自动换行，避免右列被裁。原稿没有底部导航或侧边导航（图层名如「底部导航」「标签栏」「侧边导航」，或标记 `[af:nav]`）时不再预留外侧 84 pt（`navigation-area-unreserved`）；识别到导航层时仍按模板预留。内屏竖向与桌面预设在原稿无底部导航时仅预留 24 pt 的 Home 指示条空间，报告记为 `bottom-navigation-area-compacted`。自定义窗口沿用传入的 insets。

## 读取原稿与识别页面

读取源 Frame 的节点 ID 和层级、Auto Layout 轴与尺寸模式、最小宽度、裁切与滚动属性、绝对定位子层、实例和变体属性、变量绑定与模式、文本样式和原型关联。生成前保存这份基线，便于回读对照。

按用户明确指定的区域、组件的身份与属性、图层结构和交互关系识别页面。图层名称和截图用于辅助确认。关键区域有冲突或证据不足时，使用 `generic` 计划，保留相关图层结构并指出需要复核的节点。

| 结构 | 识别线索 | 适配动作 |
| --- | --- | --- |
| 列表与详情 | 两个独立区域，列表选中项对应详情内容 | 宽区展开两个现有区域。窄区保留进入详情及返回的路径。分别记录列表态与详情态。 |
| 侧栏与正文 | 侧栏内是跨页面目的地，正文随选中项切换 | 宽区使用侧栏变体。窄区复用可访问同一组目的地的导航变体。 |
| 网格或信息流 | 重复的卡片实例或连续滚动条目 | 网格按最小卡宽重排，保留实例和顺序。信息流维持连续滚动和条目锚点。 |
| 表单或工作流 | 字段、标签、反馈和主操作具有关联 | 窄区将字段组纵向排列。错误提示紧随字段，提交和返回保持可达。 |
| 媒体与控制区 | 预览和控件各有独立语义容器 | 在合适的桌面姿态用上区显示、下区交互。保留媒体状态与控件映射。 |

## 生成可编辑目标稿

1. 每个目标从同一源 Frame 克隆，记录源 ID、目标 ID 和源到目标的节点映射。先规划，再写入。若源稿或待替换目标已被修改，基于当前内容重新规划。一次生成失败时只清理本次创建的临时稿。
2. 复用设计系统现有组件变体、属性与变量。优先调整克隆中的普通容器。实例内部需要重排而没有合适变体时，保留实例并登记人工复核。核对替换实例后的覆盖属性、样式及变量模式。 [Figma Frame API](https://developers.figma.com/docs/plugins/api/FrameNode/) · [Instance API](https://developers.figma.com/docs/plugins/api/InstanceNode/) · [变量绑定 API](https://developers.figma.com/docs/plugins/api/properties/nodes-boundvariables/)
3. 让目标根 Frame 固定为目标窗口。先确认父层为支持的 Auto Layout，再把需要占满可用空间的子层设为 Fill。随内容增长的区域用 Hug 或文本自动高度。比例媒体、固定图标和触控热区使用各自的尺寸约束。保留浮层、徽标及其他有明确用途的绝对定位。
4. 需要修改文本时，保留文字样式与混合样式。先检查缺失字体，再加载涉及的字体。对缩短文案、删除字段或替换主操作等语义改动，先在计划中标出具体节点。 [Figma TextNode API](https://developers.figma.com/docs/plugins/api/TextNode/)
5. 按需用独立 Frame 表达列表／详情、滚动前后、弹层和键盘状态。同一姿态的状态应共享目标尺寸。分屏左右各用一个目标 Frame。运行时状态恢复需要在实际应用上验证。

## 回读与验收

- 对比源稿基线和目标映射。缺失图层、实例关联或绑定丢失逐项报告，并检查跨目标稿的原型链接是否指向正确的 Frame。
- 用生成后的目标 Frame 几何校验关键标签、控件热区和前景元素。坐标需从图层局部或画布转换为目标 Frame 局部。目标有旋转或缩放时用逆变换计算。优先用真实交互区域的边界，避免把图标或投影尺寸当成热区。
- 对有意裁切的滚动区，使用滚动视口做窗口边界检查。首屏校验当前可见的前景和交互热区，同时在滚动后检查末尾项目是否能到达、是否避开固定导航及折叠区。为验收滚动内容单独提供滚动位置样本，避免把首屏外条目误报成页面溢出。
- 用截图检查异常重叠、不可读文本、长文案、RTL、弹层和键盘。Figma 可以验证这些设计状态。真实焦点、动态字体、滚动恢复和开合连续性由原型或应用实测，并在报告中标明验证来源。
- 每个目标记录源与目标节点 ID、窗口数据来源、所用规则、自动检查结果和人工复核项。发现阻断问题时标出目标节点及原因，并注明该稿需要修正。

## 建议的首轮画布样例

面板的 **列表与详情**、**组件表单** 和 **对话与结果** 会创建并选中新源稿。对话样例使用嵌在消息列表里的结果卡。用书本姿态确认报告显示「对话与结果双栏」，核对对话和输入栏同侧、结果在另一侧。用分屏左窗确认结果仍在消息列表内。列表详情样例的外屏可用 Present 检查打开与返回。表单样例可选中目标字段和提交按钮，在右侧属性中确认组件来源和颜色变量仍在。样例中的字段组件与变量是本文件的测试资产，可用现有设计系统稿进一步核对远程库实例。

| 样例 | 检查重点 |
| --- | --- |
| 列表详情页从外屏到内屏书本姿态 | 列表、详情、返回操作和选中状态的映射，完整触控热区避开分隔。 |
| 带库组件和变量的表单进入窄分屏 | 实例、变量模式、长错误文本和提交动作保留，键盘态仍可操作。 |
| 带固定导航的可滚动内容 | 首屏和滚动到底均可操作，无误报的窗口溢出，关键控件避开折叠区。 |
| 相机遮挡附近的控制组 | 用目标坐标检查真实热区，并定位到具体图层。 |
