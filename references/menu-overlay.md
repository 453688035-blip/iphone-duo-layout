# 目录与浮层交付模板

项目内有四个基础窗口：外屏闭合竖向 466 × 678、外屏闭合横向 678 × 466、内屏展开竖向 669 × 951、内屏展开横向 951 × 669（Figma pt）。先生成这四张，再按需求加书本、桌面或分屏窗口。用 [验收表](../assets/overlay-acceptance.csv) 记录 Present 测试、实际区域和未验证事项。

1. 在每个目标画板保留原稿的阅读层、固定控件和应用导航。源中已有状态组件时给该层加 `[af:status] `；不要把状态组件与背景、菜单按钮或整块应用栏打成一层。机框素材已经带镜头时，状态组件选择无镜头变体。
2. 在每个有独立交互的目标上核对菜单变体。结构可复用为「标题与关闭 / 独立纵向滚动目录 / 底部安全余量」；遮罩和浮层为同一窗口的覆盖层，不是插进正文 Auto Layout 的行。短横屏先收紧浮层外框，将滚动分配给目录；保留完整 44 pt 关闭热区、第一项和可滚达的末项。
3. 查看 `overlay-posture-review` 对应的触发层，在 Present 里检查是否仍指向旧尺寸的 Overlay / Swap 目标。需要时为目标窗口创建可编辑的浮层变体并连回对应触发器；原始连线保留到确认替代版本。记录触发层、浮层和目标画板 ID。
4. 正文滚到中段后触发、关闭；对照关闭前后的正文锚点。单独验证点击某个目录条目时定位到该章节，以及折叠／旋转后回到同一任务。Figma 原型只覆盖原型能力范围；滚动、焦点和键盘的完整验收在网页或 App 运行时做。
5. 官方组件匹配失败时查 `native-chrome-fallback`。竖轨窗口只有匹配到对应显示屏的 Duo 竖向变体、且右侧留有状态区时才插入；不拉伸通用横状态栏来填竖轨。原稿已有明确状态层时复用原稿，并检查其方向和位置。

检查原生移动端滚动时，把状态栏、灵动岛、应用标题栏和底部控件分别核对。正文滚动范围应从顶部系统区下方开始，末项应能滚到 Home 指示条或实际底部导航上方。标题栏背景可铺到机框边缘，正文、标题和交互热区仍按各自的安全区布局。导引里的底部导航尺寸用于有该组件的状态。书本和桌面半折的紫色用于 Figma 标注，展示稿可使用浅灰细线，保留布局中的折叠避让。
